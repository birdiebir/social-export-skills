# 群組模組 —— 群組互動分析（示範「輕層不做 L5、中層才做」的分層取捨）

跟 `程式\關係\` 同一套架構套用在群組對話上（POC 篩選、成員量化摘要）。**輕層預
設不做 L5 質性判讀**——這是本模組原本要示範的重點：不是每個模組都需要 LLM。原
專案 `group_analysis/` 的 docstring 明講理由：對 10 組 POC 的每個成員都做 LLM
逐則質性閱讀成本過高、不適合快速擴充，全部改用規則式／統計式方法，對 100% 訊
息做完整統計，再用簡單規則把數字轉成描述性標籤。

**這條「不做 L5」的取捨只適用於輕層**——當使用者對某個群組明確要求中層以上的
分析時，這裡就有真正的 L5 範本：`範本\中量判讀.md`（全量通讀＋事件時間軸＋精
選語錄，比照關係模組中層的品質標準，見 `分析\分層.md`）。三個範例模組裡群組模
組原本是唯一完全沒有 L5 的對照組，這條更新後改成「輕層跟原本一樣沒有 L5，中層
以上才有」，跟關係模組的差異縮小到「中層基礎素材不同」（關係模組沿用既有抽樣
摘錄 `excerpts/`，群組模組必須從零開始全量通讀 `messages_full.jsonl`，因為群組
沒有現成的代表性摘錄檔）。

## 目的與範圍

- 只排群組對話（人數超過門檻的課程/廣播型大群組排除在外——多數成員從未發言，「每個用戶的分析」對他們沒有意義）。
- 跟 `程式\關係\` 互補：關係模組處理「我和某個人」，本模組處理「一群人之間」。

## POC 篩選規則

僅用 `messages/data/thread_index.json` 既有欄位（不重掃 HTML），依序判斷排除原因：

| 排除原因 | 條件 |
|---|---|
| `not_a_group` | 不是群組對話 |
| `likely_spam` | `thread_index.json` 已算好的廣告/約會機器人判斷 |
| `manually_excluded` | 落在 `config_template.py` 的 `EXCLUDE_GROUP_NAMES` 人工排除清單 |
| `too_many_participants` | 參與人數超過 `MAX_PARTICIPANTS_FOR_POC` |

過濾後依 `message_count` 由高到低取前 `TOP_N_GROUPS` 名。跟關係模組一樣是純過濾+排序，不是加權評分——群組場景目前不需要百分位加權那麼複雜。

## 量化特徵與規則式自動標籤

對選定群組跑全量（不取樣）統計，對每個成員產出：`message_count`/`message_share`/`avg_len`/`question_rate`/`exclaim_rate`/`ellipsis_rate`/`media_rate`/`latenight_rate`/`sentiment_mean`/`initiation_count`/`top_keywords`。

**規則式自動標籤 pattern**（`分析\架構.md` L4 一節提到的通用做法）：對每個指標，取「訊息數達 `MIN_MESSAGES_FOR_TAG` 門檻」的成員裡排名前 `TAG_TOP_FRACTION` 的人，貼一個固定標籤：

| 指標 | 標籤 |
|---|---|
| `latenight_rate` | 深夜活躍 |
| `question_rate` | 常主動提問 |
| `exclaim_rate` | 情緒外顯 |
| `media_rate` | 貼圖/媒體愛用者 |
| `message_share` | 話最多的人 |
| `initiation_count` | 常主動開啟話題 |

完全規則式，沒有模型呼叫，適合對數量多的目標（10 組群組、每組多個成員）都下判斷的場景。除了成員摘要，還會產出系統事件時間軸（加入/退出/改名/換照片/設管理員）、逐月趨勢與 weekday×hour 熱力圖、異常活躍日偵測（z-score）、連續發言者互動配對排行、emoji 使用排行——這些都是純統計聚合，不需要質性判讀。

## Pipeline 執行順序

```
1. build_group_ranking_template.py  -> data/group_ranking.jsonl, data/top10.json
2. build_group_corpus_template.py   -> quant/<slug>/messages_full.jsonl（含系統事件標記）
3. build_group_features_template.py -> quant/<slug>/member_summary.json 等
4. (報告組頁，依專案既有 html_report.py 慣例組頁，本 skill 尚未提供範本腳本) -> quant/<slug>/report.html
5. (中層限定，使用者明確要求時才做) 範本\中量判讀.md -> coverage.json/events_narrative.json/quotes.json，跑完務必過 程式\共用\ 的兩支驗證腳本
```

## 已知限制

見 `分析\踩坑.md`「跨模組通用坑」「群組模組專屬」與「中層分析新增坑」三節（廣播群組排除、通用垃圾偵測假陰性、大量訊息拆批合併、語錄逐字驗證）。額外一條：`thread_index.json` 沒有「是否為企業帳號」欄位，本模組跟關係模組一樣需要人工維護的排除清單（`EXCLUDE_GROUP_NAMES`），第一次真跑後要人工檢查候選清單。

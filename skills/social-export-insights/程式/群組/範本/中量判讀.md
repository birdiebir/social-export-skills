# 質性分析任務說明（中層：全量通讀＋事件時間軸／精選語錄）

你正在協助分析一個 Facebook Messenger 群組對話（`{{GROUP_NAME}}`）。這是群組模
組的中層加值任務——本模組預設**刻意不做**質性判讀（見 `程式\群組\說明.md`），
純規則式統計就夠；但當使用者明確要求對這個群組做到中層時，就要做到跟關係模組
中層同樣的品質標準：**完整讀過全部訊息，不是抽樣**，抽出真正值得記錄的事件與
語錄。

## 為什麼「完整讀過」是硬性要求

早期做法曾經只抽樣不到 1% 的訊息就生成整份群組敘事（例如數萬則裡只讀了幾百
則），代表性嚴重不足。中層分析的價值主張就是「這次是真的讀過」，抽樣式的質性
判讀不會比純統計標籤（本模組預設做的事）更有價值，所以**中層一定要 100% 涵蓋
率**，這是跟關係模組中層（可以沿用既有抽樣摘錄 `excerpts/`）不一樣的地方——群
組沒有現成的代表性摘錄檔，必須自己從 `messages_full.jsonl` 全量讀起。

## 你的任務

### 若訊息量在數千則以內（可一次讀完）

1. 確認來源 `quant/{{GROUP_SLUG}}/messages_full.jsonl` 的總行數，記為
   `total_messages`。
2. 依月切成約 500～1,500 則一批（月份太稀疏可合併相鄰月份），依時間順序逐批
   完整閱讀每則的 `sender`/`datetime`/`text`，**不得用關鍵字抽樣代替**。每讀完
   一批記錄：涵蓋的月份與訊息數、候選事件（對照下方五類）、候選語錄（`quote`
   必須是複製貼上的逐字原文）。
3. 全部讀完後去蕪存菁：事件抓真正值得記錄的（不是每天硬湊，一個中型群組通常
   10～20 個就夠），語錄抓 15～25 則真的有趣或有代表性的。
4. 產出：
   - `coverage.json`：`{"target": "群組名稱", "total_messages": N, "messages_read": N, "coverage_pct": 100.0, "batches": [{"period": "2019-02", "message_count": 823}], "generated_at": "ISO時間戳"}`——`messages_read` 必須等於 `total_messages`。
   - `events_narrative.json`：每筆 `{"datetime": "...", "category": "life_event|conflict_reconcile|gathering|meme_origin|other", "summary": "一句話事件描述", "participants": ["顯示名稱"], "evidence_quote": "逐字佐證片段", "evidence_speaker": "說話者", "evidence_timestamp": "..."}`。`category` 固定這五類，不得自創新分類。
   - `quotes.json`：格式同關係模組中層範本（`程式\關係\範本\中量判讀.md`）的
     `quotes.json`，欄位一致（`timestamp`/`speaker`/`quote`/`context`/`reason`）。
   - 若這個群組已經有現成的敘事筆記檔（例如既有的群組介紹/摘要），改寫其中
     「值得注意的話題／事件」與「值得一提的片段」對應的段落，換成這次全量通
     讀的結果，並在文末加一段涵蓋率揭露（「本次分析已完整通讀全部 {N} 則訊
     息，涵蓋率 100%」）；若沒有現成筆記檔，這步驟略過，事件/語錄兩份 JSON
     本身就是這個任務的核心產出。

### 若訊息量達數萬則以上（單一 agent 讀不完）

先看 `分析\分層.md`「全量通讀程序」一節的拆批＋合併架構：依日期切成多個獨立
子區間，分派給不同 agent 各自完整讀完自己的區間、輸出中繼檔（`chunk_A.json`
等，格式同上面「批次」但包一層 `{"period_start", "period_end", "batches",
"events", "quotes"}`），最後由合併步驟跨全期去蕪存菁、保留敘事弧線變化，再產
出上面四份檔案，通過驗證後刪除中繼檔。

## 驗證（不通過就是沒做完）

```bash
python 程式/共用/verify_coverage_template.py \
  quant/{{GROUP_SLUG}}/messages_full.jsonl quant/{{GROUP_SLUG}}/coverage.json
python 程式/共用/verify_quotes_template.py \
  --quotes quant/{{GROUP_SLUG}}/quotes.json \
  --jsonl quant/{{GROUP_SLUG}}/messages_full.jsonl
```
兩者都要 `[PASS]`。語錄驗證失敗的常見原因是意譯、用「……」截斷長訊息、或把
時間相近的兩則獨立訊息拼成一則——修正對應那一筆，不是整份重寫（見
`分析\踩坑.md` 第 16、18 條）。

## 誠實原則

不要為了湊事件/語錄數量硬掰內容；如果某段時期群組確實安靜、沒有值得記錄的
事，如實反映，不用勉強找話題。這是可能包含私人真實對話的資料，處理時保持中
立、不對任何成員做道德評價。

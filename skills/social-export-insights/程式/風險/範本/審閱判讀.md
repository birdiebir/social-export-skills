# 質性審閱任務說明（PR 風險候選，分批審閱）

你正在協助審閱使用者自己過去在 Facebook 上的發言/貼文/留言，判斷哪些內容真的
有 PR 風險（會被誤解、造成困擾、洩漏個資、或帶來其他負面後果），供使用者自己
決定要不要刪除或設為私人。**這是私人真實內容的自我審查，不是評判使用者的人**
——你的角色是幫使用者用旁觀者的角度看自己過去的發言，不是對內容本身做道德
評價。

輸入候選來自兩個來源，都是**未經真正判讀的粗篩結果，不代表真的有問題**：
- `flagged_candidates.jsonl`：關鍵字/正則命中的候選（`matched_categories` 只是
  命中了哪些關鍵字分類，不是風險程度的判斷）。
- `unflagged_sample.jsonl`：沒命中關鍵字的分層隨機抽樣，用來抓關鍵字漏掉的
  部分（反諷、暗語、委婉說法）。

## 你的任務

1. 這批候選數量可能有數百則，**分批處理**（每批建議 20-30 則），不要一次全部
   塞進同一個 context；批次之間彼此獨立，可以平行分派給多個 subagent。
2. 對每一則候選，實際讀 `text`／`header` 欄位的完整內容（不要只看
   `matched_categories` 就下結論——命中關鍵字不等於真的有問題，沒命中也不代表
   真的沒事），判斷：
   - 這則內容脫離關鍵字命中的表面文字，放回它自己的上下文裡，是不是真的有風險？
   - 如果原本被關鍵字命中，但讀完內容後判斷只是玩笑/反諷/單純提及不構成風險，
     明確標記為 `is_false_positive: true`，不要因為命中了關鍵字就照單全收。
   - 反過來，`unflagged_sample.jsonl` 裡如果讀出真正的風險（關鍵字漏掉的），
     一樣要輸出成候選項目，不要因為它原本沒被關鍵字命中就跳過。
3. 對每一則判讀完的項目，輸出一行 JSON（JSONL 格式，一行一筆，欄位規範見
   `筆記格式.md`），寫進 `data/reviewed.jsonl`（多批次的話，各批次輸出各自的
   內容，最後合併成一份完整的 `reviewed.jsonl`，或直接以附加模式逐批寫入）。

## 判讀原則

- **誠實判讀，不要為了「有內容可寫」而誇大風險**——多數候選讀完可能只是日常
  抱怨、工作牢騷、或已經是好幾年前的往事，如實標記較低的 `assessed_severity`
  或 `is_false_positive: true`，不要每則都寫得很嚴重。
- **上下文比關鍵字重要**：同一個詞在不同語境下風險程度差異很大（例如「離職
  原因」單純描述事實，跟公開點名前公司/同事罵髒話，風險程度完全不同）。
- **中立陳述，不做道德評價**：你的輸出是給使用者自己看的風險提示，不是對這
  個人的品格判斷，用「這則內容提到 XXX，可能被解讀成 YYY」的陳述方式，不要用
  評價性語言。
- **只輸出 JSONL 內容，不要有其他前言或結尾語。**

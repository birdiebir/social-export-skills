# `reviewed.jsonl` 的欄位規範

`data/reviewed.jsonl` 是質性審閱（`審閱判讀.md`）的輸出，一行一筆 JSON，供
`finalize_pr_risk_report_template.py` 讀取分組排序。每筆紀錄的欄位：

```json
{
  "category": "posts",
  "source_file": "posts_1.html",
  "seq": 42,
  "timestamp": "2019-03-12T10:00:00",
  "header": "...",
  "text": "...",
  "url": "...",

  "matched_categories": ["workplace"],
  "is_false_positive": false,
  "assessed_severity": "workplace",
  "rationale": "一句話說明為什麼判定成這個嚴重度/為什麼是假陽性，須基於實際讀到的內容",
  "recommended_action": "刪除 / 設為僅自己看得到 / 不需處理，僅供參考"
}
```

欄位說明：

| 欄位 | 說明 |
|---|---|
| `category`/`source_file`/`seq`/`timestamp`/`header`/`text`/`url` | 直接從輸入候選（`flagged_candidates.jsonl`／`unflagged_sample.jsonl`）原樣帶過來，不要自己重新計算 |
| `matched_categories` | 原本關鍵字命中的分類，`unflagged_sample.jsonl` 來源的項目此欄位為空陣列 |
| `is_false_positive` | 讀完內容後判斷「命中關鍵字但其實沒有風險」時設為 `true`；`unflagged_sample.jsonl` 來源的項目這個欄位固定填 `false`（不適用，本來就沒被命中） |
| `assessed_severity` | 你實際判讀後的嚴重度分類，用跟 `config.SEVERITY_ORDER` 相同的詞彙（`pii_leak`/`pii_pattern`/`illegal_grayarea`/`discriminatory_offensive`/`conflict_report`/`workplace`/`political_social`），如果都不適用可以寫一個新的簡短分類詞 |
| `rationale` | 1-2 句，說明判讀依據，必須基於你實際讀到的內容，不要空泛套話 |
| `recommended_action` | 給使用者的具體建議（刪除／設為私人／不需處理），不是自動執行的指令 |

**`is_false_positive: true` 的項目仍然要寫進 `reviewed.jsonl`**（不要直接省略），
讓 `finalize_pr_risk_report_template.py` 之後可以選擇是否要在報告裡列出「已排除
的誤判」這個附加區塊，供使用者確認判讀邏輯有沒有問題。

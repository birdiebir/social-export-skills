# note.md 的 YAML frontmatter 欄位規範

每個人的 `notes/<person_slug>/note.md`（不論深層或輕層）都必須以下列 YAML
frontmatter 開頭，供彙整 dashboard 用簡易 `---` 分割＋逐行
`key: value` 解析（不依賴 pyyaml，沿用「純 Python 標準庫優先」慣例）：

```yaml
---
person: "John Doe"
slug: "John Doe__inbox__johndoe_12345"
tier: deep            # 或 light
thread_id: "inbox/johndoe_12345"
importance_score: 84.2
friend_since: "2015-03-12"   # 若無法對上好友清單則寫 null
message_count: 4213
date_range: ["2015-01-01", "2026-08-20"]
generated: "2026-08-26"
---
```

frontmatter 之後緊接著這一行（dashboard 會用 regex `\*\*一句話摘要\*\*：(.+)`
抓取顯示在排名表上，務必逐字符合這個格式，不要加其他符號或換行）：

```
**一句話摘要**：（單句，扼要描述這段關係的性質，例如「大學室友，出社會後聯絡變少但仍會互相關心近況」）
```

緊接著（若已完成人物側寫彙整，見 `人物側寫.md`）再加一行，
dashboard 用 `\*\*人物側寫\*\*：(.+)` 抓取，格式規則同上——這一行講的是「這個人」
本身的特質，跟上面「這段關係」的一句話摘要不同：

```
**人物側寫**：（單句，描述這個人整體是什麼樣的人，例如「務實內斂、重承諾，話題多圍繞工作與家庭」）
```

再接正文：
- 深層（tier=deep）：`**關係總覽**：` 一段跨季總結，接著依時間順序的逐季 `## YYYYQn` 區塊（見 `深季判讀.md`）。
- 輕層（tier=light）：單一段落區塊（見 `輕量判讀.md`），不分季。

frontmatter 裡的數字/日期類欄位（importance_score、message_count、date_range、
friend_since、thread_id、slug）都已經在 `top30.json` 與
`quant/<slug>/meta.json` 裡算好了，撰寫筆記時直接抄過來即可，不需要重新計算。

# PR 風險審閱：逐筆審閱的做法與避雷

2026-10-01 新增。內容來自兩個帳號各做一輪逐筆 PR 審閱、重寫報告、補審私訊段落的經驗。這份補充 `程式\風險\說明.md` 和 `程式\風險\範本\審閱判讀.md`，那兩份已經寫過的不重複。頁面遮罩的技術做法見 `social-export-analysis` 的 `references\privacy.md`。

## 1. 審閱結構：逐筆、有錨點、可回溯

- 散文報告不算審閱完成。舊做法只有候選清單，結論寫在一篇散文報告裡，結果沒辦法驗證，也沒辦法做成清理清單。要改成**逐筆審閱檔**，每筆有：
  - `risk_level`：高／中／低但建議刪／不需處理
  - `recommended_action`：刪除、收回、隱藏、不處理……
  - 判讀理由
  - **錨點**
- 錨點用來對回 L1，審閱檔本身不存全文。錨點有三種：
  - 逐字引文（子字串對回 L1）
  - 原文連結（url）
  - 整串私訊（thread_id）
- 產生器依錨點回溯 L1，verify 檢查「審閱結論 N/N、清理清單 M/M、待審 0」。
- **`scope: segment`**：一段很長的群組私訊，可以只審其中一個日期區間（例如某天的爭執），不用整串審。審閱檔記下起訖時間，頁面也顯示是哪一段。
- **待審登記**：關鍵字掃不到、但使用者或其他模組點名的內容（例如另一個 agent 讀對話時發現的辱罵段落），先登記到 `_待審\`，只記出處和理由、不收原文，下一批再逐筆審。驗證時「待審」要歸零才算完成。

## 2. 判準要寫下來，跟使用者確認後維持

- 判準由使用者定，寫進決策紀錄，之後每一批都照同一套。虛構範例：「沒有辱罵字眼、不針對個人的政治評論不需處理；對群體的辱罵列為低優先刪除。」
- 不要每一批各自調判準。重寫報告時，附上新舊報告的差異對照，說明每一項是改判、新增還是移除，以及理由。
- 舊報告存 `_superseded\`，不要刪。

## 3. 性質判斷有些只能問使用者

- **洗版、廣告、異常大量發文**可能是帳號被借用或被盜（例如「借帳號賺錢」詐騙）。內容一樣要清，但性質不同：不是本人的言論，報告和筆記的寫法也要跟著改。資料看不出成因時，標「待使用者確認」，不要自己推定。
- **地址、物件、電話是誰的**：本人貼文裡出現的地址，可能是幫朋友貼的。要不要列進本人地址豁免清單，只能問使用者，問之前一律遮。
- **未成年時期的發言**要用當時年齡的標準判斷（見 `踩坑.md` 風險模組第 16 點）。

## 4. 清理清單的穩定性

- 清理清單的勾選狀態用項目 id 存在瀏覽器（localStorage）。項目內容或遮罩改變，可能讓 id 跟著變，勾選就被重置。
- 使用者還沒開始清理時改，沒有影響。開始清理以後，id 要保持穩定（用錨點產生 id，不要用內文產生），或在報告裡明確告知哪些項目的勾選被重置。

## 4b. 使用者確認成因之後怎麼改（2026-10-01 新增）

例如：某段洗版經使用者確認，是帳號被借用時別人發的。處理方式：

- **只改寫錯成因的句子**。審閱判定、風險等級、清理建議都不變：內容還掛在帳號名下，照樣建議刪除，只是性質從「成因不明」改成「帳號被借用」。原本「去查登入紀錄」這類為了判斷成因而列的待辦可以拿掉。
- **同一段期間的其他內容要分開確認**。洗版期間同一帳號還有幾則私訊，是不是本人發的要另外問，不要一律推定成「也是別人發的」。實際上那幾則私訊也可能確認是本人發的。
- **影響範圍要一次掃完**：逐筆審閱檔的判讀理由、PR 報告（成因、時間軸、建議行動）、社團總和篇、相關社團筆記、個人動態（時間重疊的相片只寫「時間重疊」，不推定是誰傳的）。
- **不改的也要列出來**：原樣保存的舊文件、未採用的審閱版本不改，但要在勘誤條目的「原文位置」列出它們，讀的人才知道那裡還留著舊說法。
- 只寫結論，**不寫借用者的細節**。
- 改這類內容常常需要大量改寫筆記，可能被自動模式的權限分類器擋下。處理方式見 `social-export-analysis` 的 `references\parallel-agents.md`。

## 5. 範圍決定要記錄「不做」

- 例如：其餘已分析的私訊不做 PR 掃描、無文字相片不做看圖判讀。這類「不做」的決定也寫進決策紀錄，附上理由。之後的 PM 或 agent 盤點剩餘工作時，才不會把它們當成漏做的項目。

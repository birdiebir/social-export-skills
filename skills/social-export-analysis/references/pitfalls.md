# Pitfalls from later iterations: export quirks and verification blind spots

Added 2026-10-01. These come from rebuilding the pipeline as a single codebase that processes two exports of the same person and running it through many batches of fixes. Each item is written as symptom → cause → what to do.

Read **section A** before writing or changing any parser. Read **section B** before you trust a PASS from a coverage, regression or quote check.

Examples use made-up names and values.

## A. Meta (Facebook) export quirks

1. **Message file names get truncated from the end when the path is too long.**
   - Symptom: some thread folders contain `message.html`, `mes.html` or just `.html` instead of `message_1.html`. A strict regex like `message_\d+\.html` skips them without any error. Whole short threads go missing, and in the source project every check still passed (see B1).
   - Related: an entire thread folder can also be collapsed into a single `<name>_<id>.html` file next to the other folders.
   - Do: treat any `.html` directly inside a thread folder whose stem is a prefix of `message_<N>` (including an empty stem) as a message page. Treat a missing page number as page 1. Record `message_files` and `truncated_message_files` in the extractor's manifest so coverage can check against them. Implemented in `scripts/connectors/facebook_html/fb_common.py` (`find_message_files`, `message_page`).

2. **The text field of a sticker, like, photo or attachment message may contain only "IP address: …".**
   - Symptom: a reader (human or LLM) sees a line like `IP 位址：203.0.113.7` and writes "system notice" or "the user didn't reply". In fact the user sent something, usually the Messenger thumbs-up sticker. Keyword extraction also picks up "IP" and "address" as top terms.
   - Cause: in some exports (seen in an older account's export) Meta puts the sender's IP into the text slot when the message has no typed text.
   - Do: classify by the record's `type` and `media` fields, never by text alone. In excerpts handed to an LLM, render these as `[sticker]` or `[photo]` instead of the raw text.

3. **Timestamps are rendered in one fixed timezone, not where the user was.**
   - Symptom: the export shows an event on the 15th, but it happened on the evening of the 14th local time (the user was abroad).
   - Do: write the export's timezone into the L1 data spec. When a narrative names a date for something that happened abroad, convert to local time first. Dates near midnight are where narratives go wrong.

4. **Meta AI conversations attribute the AI's replies to the user.**
   - Symptom: the HTML says "generated by <user name>" on the AI's turns, so the parser sets `sender = self`. Self-message counts and "things the user said" then include AI text.
   - Do: flag these threads (`ai_sender_unreliable`), and exclude AI turns from self counts and quotes. Check both exports, since the same AI chat can appear in each.

5. **Second-person template sentences get counted as the user's speech.**
   - Examples: "You started a call", "You sent 1 attachment", the Marketplace pre-filled "Is this still available?", memorialization-contact notices, "You named the group …".
   - Cause: the export writes them as messages from the user.
   - Do: tag them `system` or `template` before counting "how many messages did the user write", and never quote them as the user's words. Expect small count changes downstream when you introduce the tag, and explain them in the regression report.

6. **A section with no sender (no `aria-labelledby`) gets swallowed into the previous message.**
   - Symptom: the previous message's text ends with a stray timestamp or a sentence like "X set the nickname for Y…". Its `dt` becomes the system section's time, so it can move by hours.
   - Do: split at the footer boundary. Emit one `sender=None, type="system"` record per section, even an empty one, so section accounting balances. Implemented in `fb_common.iter_messages()`.
   - Counting: keep `message_count` meaning "messages with a sender", because rankings, thresholds and coverage denominators depend on it. Add `system_count` and `record_count`, and use `record_count` only for pagination and line accounting.

7. **Participant lists join the last two names with a conjunction.**
   - Symptom: `A、B、C和 D` (Chinese UI) gives `C和 D` as one name.
   - Do: split on the last conjunction only when the right-hand side is a known speaker or a self alias. Names that really contain the character must not be split.

8. **Rename events disappear when a name-length cap meant for people also applies to group names.**
   - Symptom: "X named the group <long title>" isn't recognized as an event. Marketplace threads often start with exactly this sentence, using the listing title.
   - Do: use a separate, longer cap for group names, and keep the timestamp-noise guard.

9. **Message text can contain U+2028 or U+2029.**
   - Symptom: `str.splitlines()` splits one JSONL record into two broken lines.
   - Do: iterate the file with `for line in f` or split on `\n` only (`fb_common.iter_jsonl()`).

10. **Some raw HTML files are never read by any extractor.**
    - Examples: ad interests, off-platform activity, album frame pages, settings pages.
    - Do: at extract time, write the list of unconsumed HTML files (for example `_unconsumed_raw_html.json`). The coverage check then forces every raw file to end up somewhere: a parsed record, a generic fallback page, or an exclusion list entry with a reason.

11. **pip on a Windows CJK codepage reads `requirements.txt` as cp950.**
    - Symptom: a Chinese comment in the file breaks `pip install`.
    - Do: keep `requirements.txt` ASCII-only.

12. **The same thread can exist in two exports** (shared groups, self-notes between two accounts). See `multi-account.md` before counting or analyzing across accounts.

## B. Verification blind spots

1. **Coverage by inference passes on missing data.**
   - Symptom: the rule "every HTML deep enough under `messages/` counts as read" marked truncated files (A1) as read even though they were never parsed. Coverage and regression both said PASS while hundreds of messages were missing.
   - Do: compare against the read list the extractor actually wrote (`message_files` in the manifest). FAIL any thread-level HTML that isn't on it, and require attachment-type HTML to be referenced by some media link. If an old manifest has no read list, fall back to the old rule and print a warning that says so. Template: `scripts/coverage_check_template.py`.

2. **Deciding "is this file referenced?" by path misjudges duplicate content.**
   - Symptom: media are stored once per sha256 under the first path's name, so every other path with the same content looks unreferenced. The orphan page then fills with thousands of files that are already shown elsewhere.
   - Do: decide referenced-ness by sha256. If a hash really is unreferenced, list only its first path (`select_orphans()` in `scripts/coverage_check_template.py`).

3. **Mechanical checks can't see semantic errors.**
   - Quote substring checks plus coverage counts can PASS while the narrative is wrong.
   - Notes written from samples had very high error rates when checked semantically: in one batch, almost every sampled-era note needed corrections.
   - Do: base conclusions on full-read notes and treat sampled notes as drafts. The semantic review procedure is in the `social-export-insights` skill (`分析\分層.md`, `分析\查證與協作.md`).

4. **A check that writes a shared multi-account file must merge, not overwrite.**
   - Symptom: a regression run limited to one account (`--account X`) rebuilt the cross-account `_unconsumed_raw_html.json` from account X alone. The other account's fallback pages vanished on the next package run.
   - Do: read the existing file, update only the keys for this run, and write it back. Until that's fixed, the wrap-up checklist must say "don't scope this command", and you must assert afterwards that the file still has every account key.

5. **Numbers from different stages can rest on different definitions.**
   - Things that differ between stages: whether system records are included, whether template sentences are included, `>=` versus `>` on a cutoff date, text-only versus all messages.
   - Example: counting "messages after the switch date" with `>=` included the switch day itself and inflated the result by about a fifth.
   - Do: before comparing two numbers, write down both definitions. Most mismatches are definition differences, but some are real bugs, and you only find out which after the definitions are aligned.

6. **Verify parser fixes against a snapshot.**
   - Do: before changing a parser, snapshot the L1 output. After the change, diff everything. Threads that the change shouldn't touch must be byte-identical, and every changed record needs an explanation in the regression report.
   - The snapshot contains private messages. Keep it in a gitignored temp folder and delete it once the batch passes.

## C. Additions from the second round of fixes (2026-10-01)

1. **Measure how big a fix is before you choose how to make it.**
   - Symptom: a fix was planned as "relabel template sentences as `system`", based on an estimate of a few dozen messages. Measured across both exports, it was **tens of thousands**: the estimate was off by almost three orders of magnitude.
   - Cause: estimates come from the slice you happened to look at. Template sentences such as call notices, attachment frames and nickname changes are spread across every thread.
   - Do: run a read-only trial calculation first and record the counts. Here, relabeling would have changed `message_count`, and every ranking, threshold and coverage denominator built on it would have drifted. So the fix became an **added flag** (`template: <kind>`) plus an `is_typed()` helper for analyses that need "messages the user actually typed". `type`, `sender` and `message_count` stayed as they were. Prefer adding a field over changing the meaning of an existing count.

2. **Reactions stuck to the end of message text.**
   - Symptom: L1 `text` ends with "emoji + person's name" (a reaction to that message). Quotes copied from L1 pick it up, and strict quote checks either fail or pass with the tail included.
   - Do: split reactions into their own field during extraction. Until then, strict quote checks must not accept a quote that includes the reaction tail.

3. **Infer the AI's turns in AI-assistant chats by pairing question and answer.**
   - Do: pair self-labelled messages in an AI conversation as question → answer, using a time window (for example, the next self-labelled message within 10 minutes). Move the answer to the AI and add `ai_reply_inferred: true`. Records not labelled as the user (for example "AI named the group …") stay out of the pairing.

4. **Write-back scripts for user-filled checklists: dry-run first and look at the change count.**
   - Symptom: a checklist had one "your decision" column per row. The user instead wrote one line, "all yes", under the section heading and left the per-row cells empty. The dry-run reported "0 people changed, all questions skipped as unknown/blank", because the script only read the per-row cells. Nothing was written, but it would have been easy to report "applied" without noticing. Once the answers were converted into an answers file, the write went through as expected.
   - Do:
     - Make the script dry-run by default. It should print how many records change and the tier counts before and after.
     - Treat "0 changes" as a red flag, not a success.
     - Refuse to write if the in-memory verify fails.
     - Accept section-level answers explicitly (or ask), and say in the checklist itself where to answer.
     - When answers come through chat, save them to a UTF-8 file and pass `--answers-file`. Chinese passed as a command-line argument gets garbled by the console codepage.

5. **Delete only after a full verification chain.**
   - Order for deleting old raw copies: back up the source of truth → read the backup back 100% and verify it, plus restore a few files and compare SHA-256 → do a full SHA-256 comparison proving the copy to delete is a **subset** of the source of truth (0 mismatches) → user approves → delete.
   - "It's probably the same files" is not enough. The only copy of an export is irreplaceable.

6. **Output folder names that include the month create a second package when the month changes.**
   - Symptom: the package folder is named `<name>_YYYY-MM`. The first rebuild in a new month wrote a new folder next to the old one, the output tree doubled in size, and both versions looked current.
   - Do: after a successful check of the new package, delete the old one (with the user's approval, since that's a big deletion) or keep exactly one, and say so in the wrap-up report.

7. **Tests guarded by `skipUnless(path.exists())` silently stop testing when a script moves.**
   - Symptom: a helper script was moved out of a scratch folder that later got emptied. The tests pointed at the old path, so 5 of them were skipped, and the run still printed "OK" with the same total.
   - Do: in acceptance, read the `skipped=` count, not only "OK". After moving scripts or clearing scratch folders, rerun the suite and confirm skips did not go up. Prefer pointing tests at the permanent `tool/scripts/` location.

8. **Check results that only print to the terminal can't be audited later.**
   - Symptom: the final reviewer could not verify "links 0 problems, portability PASS" because the only evidence was another agent's chat report; the JSON report lived in a git-ignored build folder that gets overwritten.
   - Do: have the check command also append one summary row (time, commit, counts, PASS/FAIL per check; no paths, names or message content) to a git-tracked log file in the workspace, plus a human-readable `.md` next to the JSON.

## D. Additions from a broad optimization round (2026-10, many parallel agents)

1. **Two exports can label the same deactivated account differently.**
   - Symptom: in one export, messages from a since-deactivated account were split off as `system` records; in the other export, the same account's messages are attributed to a generic placeholder sender ("Facebook user"). The same group thread then has different message counts on each side (up to a hundred or so missing on one side).
   - Do: when comparing mirrored threads, check placeholder senders and system records before concluding that one side is incomplete. Normalize both to one labelling at extract time, and re-extract so the change takes effect.

2. **Some timestamps are re-stamped by Meta and don't reflect when the action happened.**
   - Symptom: pages liked years earlier on an old account showed up again with dates years later. A "when did each interest start" timeline built from those dates is wrong.
   - Do: for interest and history timelines, prefer the original action records (profile-update entries such as "added X to profile", and group membership records). Treat bulk re-dated records as "existed by this date", not "started on this date".

3. **AI-assistant conversations aren't only in the AI folder.**
   - Symptom: excluding threads by subfolder (`ai_conversations`) missed AI chats that sit in the normal inbox (thread IDs starting with the AI's name). Their turns were counted as the user's messages in yearly stats.
   - Do: provide one `is_ai_thread()` helper (subfolder **or** thread-ID pattern) and have every stats module use it.

4. **Template-sentence patterns keep growing, and new ones only apply after re-extraction.**
   - Examples found later: "<name> sold <item>", "We've told them you're waiting for a reply", "<name> sent a group link". The user typing "sold!" by hand is **not** a template.
   - Do: add a pattern plus a test using fictional names, then run a read-only trial count. Note in the decision log that downstream "typed message" counts stay slightly inflated until the next approved re-extraction.

5. **Writing files on Windows can silently change line endings.**
   - Symptom: a masking script used Python's text-mode `write_text`, which turned LF into CRLF in files stored as-is in git (`-text`), producing whole-file diffs. Its inserted YAML block was also invalid.
   - Do: for in-place edits of notes, read and write **bytes** (or `newline=""`) and keep the original line ending. Parse the YAML you wrote back in a test.

6. **Heavy jobs running in parallel can get packaging killed.**
   - Symptom: while several agents were re-running modules and reading large files, the packaging step was stopped by the OS for lack of memory. A rerun with nothing else running passed.
   - Do: run packaging and the full check alone, after the other agents finish. Keep the machine awake (see `parallel-agents.md`).

## E. Additions from a long-tail analysis round (2026-10, ~150 small threads read in full)

1. **A call record's timestamp is when the call ended.**
   - Symptom: a note said "called at 15:18", but the record (15:18, 15 minutes) means the call started around 15:03.
   - Do: start time = record time − duration. Verified on several calls against surrounding messages.

2. **"The other side's messages are all blank" is usually an export gap, not a parser bug.**
   - Symptom: in several threads one participant has dozens of messages with a sender and timestamp but no text, attachment or reaction. Some threads also have system-like sections with no sender at all.
   - Cause: in the raw HTML those sections already contain only the sender heading and timestamp; the content div is empty. In one export this was about 9,800 sections across ~500 threads.
   - Do: check the raw HTML structure once (print tags and character counts, not content). If it's empty there too, write "content not visible" and stop. Don't guess what was said, and don't attribute sender-less records to any particular person, including a placeholder sender like "Facebook user".

3. **Reaction-only sections get counted as typed text.**
   - Cause: the cleaner ran `strip_tags` over the whole section, so the reaction list (`ul._a6-q`) became the message `text`. A section with empty content and one reaction then looks like the other person typed something.
   - Effect: inflated "typed message" counts, share of speech and "who started it" for the other side (a few hundred sections in one export).
   - Do: extract the reaction list into its own field before taking text. Until re-extraction, treat `text` that is only a reaction as not typed.

4. **Untagged sections right after a thread-metadata block are silently dropped.**
   - Symptom: the raw file has N timestamps, L1 has N−1 records. The missing one sits right after a metadata section (for example "group invite link") at the top of the newest page.
   - Cause: the embedded-section split (A6) ran only when the header regex matched; metadata chunks took the other branch and `continue`d, and the stats only said `skipped_header`.
   - Do: split embedded sections in metadata chunks too (first part = metadata, the rest = system records), but skip sub-blocks that are part of the metadata itself (for example text-effect settings). Add "sections found inside metadata chunks" to the coverage ledger so this can't hide again.

5. **Automatic texts without a template flag keep turning up, and some sentences are flagged already.**
   - Examples: mentorship-programme reminders, pre-filled request sentences, "you opened this conversation from an ad", friendship-anniversary notices, missed-call notices under the other person's name, quick-reply button labels under the user's name, "<user> added X to the group" with no event flag, "1 contact added 1 participant".
   - Also: subtract unsent (`type=unsent`) messages from typed counts; names shown in system texts are usually the nickname at export time, not at that date; compare emoji by codepoint, because variation selectors differ.
   - Do: check whether L1 already flags a sentence before subtracting it by hand (one "you left the group" pattern was already flagged in every case). Register new patterns with fictional-name tests, and note in the decision log that counts stay slightly off until the next approved re-extraction.

6. **Daylight saving changes twice a year.**
   - Symptom: a stay abroad converted with one fixed offset puts events near the switch dates on the wrong day; summaries and titles kept the export's date even where the body was converted.
   - Do: convert with a named timezone (`zoneinfo`, for example `Europe/Paris`), write the actual switch dates next to the stay in the places file, and convert dates in one-line summaries and titles too.

7. **Splitting a thread ID out of a folder name on the first `__` breaks on names that end in an underscore.**
   - Symptom: a notes folder `<name>__<sub>__<folder>` whose name is `9_99_` became `9_99___inbox__…`; splitting on the first `__` gave `_inbox__…`, nothing matched the thread index, and one analyzed thread lost its "analyzed" link in the package. Other modules counted notes folders and showed the right number, so the two totals disagreed by one.
   - Do: prefer the thread ID stored in the note's meta file. Otherwise split from the right at the last `__` followed by a known subfolder name (`inbox`, `archived_threads`, `message_requests`, `filtered_threads`, `e2ee_cutover*`, `ai_conversations`), and only then fall back. When you fix one occurrence, grep every tool for the same split pattern; here three more call sites had the same bug.

8. **`glob` skips folder names that contain `[` or `]`.**
   - Symptom: a scan over notes folders found 79 of 80; the missing one was named like `[Official] admins`. Glob reads the brackets as a character class.
   - Do: list directories with `os.listdir` / `os.scandir` (or `glob.escape` the literal part), and compare the count with an independent listing.

## F. Additions from a first Instagram export (2026-10, HTML format, single account)

1. **Instagram HTML shows every time in a fixed UTC-8, all year (no daylight saving).**
   - Evidence: `login_activity.html` titles each entry with an ISO UTC time; every displayed time was exactly 8 hours earlier, across all 12 months.
   - Effect: read as local time, the user's message-hour profile looked like they were most active at 3 a.m.
   - Do: parse displayed times as UTC-8 and convert to the user's home zone in the extractor, then verify the rule against the login titles before trusting any hour or date.

2. **Converting the parsed records is not enough: hand-copied single dates stay wrong.**
   - Symptom: counts and yearly tables were correct, but the report's sign-up date, rename date, Threads onboarding date and first/last story dates were one day early. They had been copied from the HTML while writing, not taken from the converted `ts`. An independent check found 3 of 12 facts partly wrong (25%) and the batch was redone.
   - Do: write every date in a report or note from the converted field. Before sending facts to a check, grep the draft for dates and confirm each one against the converted data.

3. **Same file names in different Meta products collide.**
   - Symptom: the Threads folder in an Instagram export also has `following.html` and `followers.html`. Keying records by file stem merged Threads with Instagram, and "following" came out about a third too high.
   - Do: key by the path relative to the export root, or prefix the product folder.

4. **The messages folder mixes products and event types.**
   - The Instagram `messages/` total also included Threads DMs, message requests, and like/reaction/blank events, each counted as one record. Name the scope when you write "Instagram DMs".
   - One long thread split into exactly 10,000 + 1,000 records may have hit an export cap. Write "at least N".
   - Only group-thread files start with a `Participants:` header (no timestamp); one-to-one files don't.

5. **A single export can't tell you who unfollowed you.**
   - Only the current follower list is exported, plus an unnamed count of recent unfollows. DM senders appear by display name only, with no username, so most DM contacts can't be joined to the follower list automatically.
   - Do: save each export's follower list and diff consecutive exports (a followers-and-following-only export in JSON is small and quick). Show display-name lookalike usernames only as hints, never as matches.
